# Change: Don't leave the request container in the ASGI scope

**Lane:** lightweight — 4 LOC net in one module, one added test, no public-API
change.

## Goal

Every request through `_DIMiddleware` produced a reference cycle, so the
per-request container and everything it reached could only be reclaimed by the
garbage collector, never by reference counting.

Measured on a minimal Starlette app, 200 requests, GC disabled during the run:

| modern-di | this integration | cyclic objects per request |
|---|---|---|
| 3.0.0 | as-is | 34 |
| 3.1.1 | as-is | 34 |
| 3.0.0 | with this change | 34 |
| **3.1.1** | **with this change** | **0** |

Bare Starlette with no DI at all produces **0**, so all 34 were ours.

## Approach

There were two independent cycles and both had to go:

1. `container → _scope_map → container` — every `Container` stored itself in its
   own scope map. Fixed upstream in modern-di 3.1.1.
2. `container → context → Request → Request.scope → container` — **ours.** The
   middleware puts the child container into the ASGI scope, and the container's
   context holds the `Request` that owns that scope.

This change breaks the second: the scope entry is removed when the request
finishes, in a `finally` so it also runs when the app raises. The container is
already bounded by the `async with` around it, so nothing may read the entry
after that block exits — the entry outliving the request was the bug, not a
feature.

`modern-di-fastapi` does not have this problem: it exposes the container through
a yield dependency rather than the ASGI scope, so nothing points back at it.
`modern-di-fastapi` and `modern-di-litestar` put the *root* container in
`app.state`, which is a process-lifetime singleton, not per-request.

## Files

- `modern_di_starlette/main.py` — `_DIMiddleware.__call__` clears
  `_CONTAINER_SCOPE_KEY` in a `finally`.
- `tests/test_middleware.py` — test that a completed request leaves no cyclic
  garbage, and that the scope entry is gone afterwards.
- `pyproject.toml` — `modern-di` floor `>=3,<4` → `>=3.1.1,<4`. Required, not
  cosmetic: the new test fails against 3.0.0, which the old range permitted.
- `architecture/container-lifecycle.md` — records that deleting the entry is
  load-bearing.
